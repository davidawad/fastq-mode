# AGENTS.md — fastq-mode

Emacs package: a major mode and a streaming, never-load-the-file viewer
for FASTQ sequencing reads (.fastq, .fq, gzipped or not, any size).
README.md is the user reference.

## Layout

- `fastq-mode.el` — entry point: `fastq-mode`, eldoc, record commands,
  `fastq-open`, `fastq-auto-view-mode`.
- `fastq-core.el` — pure functions: record layout, Phred offsets/bins,
  header decoding (CASAVA 1.8+ and pre-1.8), mate file names.
- `fastq-font.el` — faces and record-aware font-lock (line role comes from
  the line number, never from regexps: quality lines may start with @/+).
- `fastq-stream.el` — chunked sources (plain byte ranges, `gzip -dc` pipe,
  zlib fallback) and line/record streaming. The only file that reads FASTQ
  data from disk or runs gzip.
- `fastq-view.el` — the paged viewer and its plain-file checkpoint cache.
- `fastq-stats.el` — read/quality statistics; optional seqkit.
- `examples/` — demo data generator and the screenshot renderer.

## Changing it

- `make test`, `make compile` (warnings are errors) and `make checkdoc`
  must pass; `just test-gate` runs all three. Without make (Windows):
  `emacs -Q --batch -l test/run-tests.el [test|compile|checkdoc|all]`.
- CI: `.github/workflows/test.yml` is the fast push check (Linux, Emacs
  30.1). `ci-full.yml` is the Linux/macOS/Windows x Emacs 29.1/30.1 matrix;
  run it with `gh workflow run ci-full` before tagging, or let tags run it.
- Cross-platform: find programs with `executable-find`, run them with
  argument lists (no shell), build paths with `expand-file-name`, read and
  write fixtures with no coding conversion. Tests must pass on all three
  OSes; skip only when a tool is genuinely absent (gzip on stock Windows,
  where the zlib path is exercised instead).
- Never load a whole FASTQ file into a buffer outside `fastq-mode` on small
  files: everything else streams through `fastq-stream.el`.
- Fixtures (`test/fixtures/`) and demo files (`examples/`) are synthetic,
  regenerated by `make fixtures`. Never read real sequencing data in tests.
- Errors: `fastq-error` via `fastq--error`; user mistakes are `user-error`.
- Task tracking: br beads (`.beads/`), one worktree per bead.
